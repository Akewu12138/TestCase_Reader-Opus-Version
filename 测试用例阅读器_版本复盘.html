01

复盘背景：问题从哪来

依据《问题复盘.xlsx》记录，本版本周期共沉淀 2 个核心问题。两者分别指向「测试执行方式」与「测试过程管理」，是本次工具与流程双线改进的直接动因。

问题一 · 缺陷漏测

关键帧重定位功能丢失

根因分析
Excel 测试用例整表显示太杂，导致用例理解错误——将「重定位」用例测成了「初始定位」，重定位功能缺陷因此漏测。
改进措施
✔ 使用用例阅读器工具，将用例拆解为一条一条独立执行，从根源规避相似用例混淆问题。
问题二 · 排期失准

测试排期不准

根因分析
1、rc 版本间出现重大问题未及时打回；
2、测试内容评估不准，导致时间不足。
改进措施
✔ 出现重大问题直接版本打回，不再接受 test 包进行测试；
✔ 使用人力排期表格记录每日实际投入人力，建立工业测试时间评估体系。
复盘结论：问题一的本质是「执行介质」问题——大表 Excel 不适合逐条精细执行；问题二的本质是「过程度量」缺失——没有打回红线，也没有人力投入基线。因此本周期确立两条改进主线：工具侧打造逐条执行、结果留痕的用例阅读器；流程侧建立版本打回机制与人力排期评估体系。
02

项目全景：测试用例阅读器是什么

基于 Flask + openpyxl 的轻量 Web 工具，将 Excel 测试用例变为可交互的执行界面：逐条浏览、四态标记、实时回写原文件。定位为「Excel 就地执行器」——轻量、零迁移，Excel 始终是唯一数据源。

组合筛选 + 冒烟/复测预设
🗂️

Sheet 自动分类

前 6 行定位表头，自动区分功能用例 / 场景用例 / 结果矩阵 / 信息页，只读与可执行分流。

🧩

通用列解析

按表头名 + 同义词别名（field_aliases.json）解析列，兼容多种表头布局，不依赖固定列序。

🖼️

内嵌示意图提取

自动提取 Excel 锚定图片，场景卡片与矩阵预览按需惰性加载展示，不拖慢首屏。

✅

逐条执行四态标记

PASS / FAIL / BLOCK / 跳过，记录实际现象、发现时间、BugID、测试人员，防抖自动保存。

⌨️

键盘流水线操作

←/→ 切换用例、1/2/3/4 快捷标记、「下一条未测」一键跳转，专为高频执行设计。

🔁

多轮次结果列

rc9 / rc10 / rc11 各轮次独立结果列，＋新建列即开新一轮，按选中列统计进度。

🛡️

原子写回 + 自动备份

临时文件 + os.replace 原子替换原 xlsx，线程锁防并发，首次访问自动备份（保留最近 10 份）。

🚀

双击即用

start_windows.bat / start_mac.command 一键建环境、装依赖、起服务，浏览器打开即用。

技术栈说明
后端Python / Flask / openpyxl（3.0–3.2，图片提取依赖私有 API 已锁定版本）/ Pillow（保证内嵌图片不丢失）/ waitress 生产服务（未装自动回退）/ xlrd（旧版 .xls 上传自动转换）
前端原生 HTML + CSS + JavaScript，无框架依赖，单页应用
数据Excel 为唯一数据源；uploads/testing 用例库 + uploads/backups 自动备份区
质量tests/test_excel_service.py 核心逻辑单元测试（433 行），推送前必跑
