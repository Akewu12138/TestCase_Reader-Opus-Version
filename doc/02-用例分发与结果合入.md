# 用例分发与结果合入（团队协作测试）

## 需求摘要

- 分发：主测在现有筛选范围（`visibleIndices()`）基础上点"导出子任务"，可选填"分发给"（写入主文件测试人员列），生成精简版子集 xlsx 下载给辅助人员。
- 执行：辅助人员用本工具或 Excel 打开子文件，填写测试结果、实际结果、BugID、备注等。
- 合入：主测点"导入结果"上传子文件，预览比对（主文件现值 vs 子文件新值），默认只勾选空缺项，确认后写回主报告。
- 已确认决策：精简版子集文件；元数据精确 + 模糊兜底匹配；预览确认 + 默认不覆盖；导出时可选记录分配；子文件只带当前选定结果列。

## 后端：excel_service.py

### 子任务导出
- 新增 `export_subtask(path, targets, tester="", result_header=None, out_dir=None)`：
  - `targets` 为 `[{sheet, rowIndex}]`（前端 `visibleIndices()` 映射提供）；按 sheet 分组，每组生成与源 Sheet 同名的工作表：表头行位置与列结构同源（含全部可编辑字段列），仅保留目标用例行（原相对顺序，连续不留空行），不复制图片与分组行。
  - 结果列只保留 `result_header` 指定的一列（默认解析出的主结果列）；其余结果类列不写入。
  - `tester` 非空时：源文件对应用例的测试人员列写入该名字（走 `_atomic_save`，复用现有写锁）；子文件测试人员列预填同名。
  - 元数据：子工作簿新增隐藏 Sheet `_qoder_map`，行级记录 `{sourceFile(文件名), sheet, rowIndex, caseId, title, steps 前 40 字, fingerprint(sha1(caseId|title|steps 规范化))}`，首行记导出时间与源结果列表头。
  - 返回生成的临时文件路径（`uploads/tmp/子任务_<主文件名>_<时间戳>.xlsx`）。

### 合入解析与匹配
- 新增 `parse_subtask_for_merge(main_path, sub_path)`：
  - 校验 `_qoder_map` 存在；`sourceFile` 与主文件 basename 不一致时返回警告（允许用户确认后继续，走模糊匹配）。
  - 逐条匹配：先按 `(sheet, rowIndex)` 取主文件用例，校验 `caseId/title/fingerprint` 一致即精确命中；不一致则在该 Sheet 内按 `caseId` 精确 → `title` 模糊（新增 `_similarity`，阈值 `_FUZZY_THRESHOLD=0.82`）→ `steps` 模糊兜底；命中记录主文件 `rowIndex`，全部失败进 `unmatched` 列表。
  - 输出预览数据 `items`：每条含 `{subRow, sheet, 匹配状态, caseId, title, mainRow(可空), 主文件现值{result/actual/bugId/note/foundTime}, 子文件新值{同字段}}`；`conflicts` = 双方均有值且不同的条目；`resultHeader` = 子文件结果列表头名。
  - 校验子文件结果列表头：主文件结果列（`_result_columns` 表头集，`_norm_header` 归一比较）中不存在该表头时，返回错误提示"主文件缺少结果列 X，请先在主文件补齐该列"，不进入预览。

### 合入写回
- 新增 `merge_subtask_results(main_path, sub_path, approvals)`：
  - `approvals` 为 `[{sheet, mainRowIndex, fields:{result?, actual?, bugId?, note?, foundTime?}}]`（仅含用户勾选的字段）。
  - 持写锁：逐条重新校验目标行 fingerprint（防预览期间主文件被改动，不一致即中止该条并计入失败清单）；结果字段写入 `_norm_header` 匹配子文件结果列表头的列（缺失即报错）。
  - 逐条写后一次性 `_atomic_save`；返回 `{merged, skipped, failures:[{title, reason}]}`。

## 后端：app.py

- `POST /api/subtask/export`：body `{targets, tester?, resultHeader?}`，校验 targets 非空；调 `export_subtask`，读字节经 `io.BytesIO` 下发（避免流式发送时 Windows 句柄占用导致删除失败），下发前删除临时文件。
- `POST /api/subtask/import-preview`：multipart 上传子文件，存 `uploads/tmp/`，调 `parse_subtask_for_merge`，返回预览 JSON 与子文件临时路径 id。
- `POST /api/subtask/merge`：body `{importId, approvals}`；调 `merge_subtask_results`；成功后清临时文件并刷新解析缓存（`_atomic_save` 已使指纹失效）。
- `uploads/tmp/` 目录启动时确保存在；超过 24h 的残留临时文件启动时清理。

## 前端：static/index.html

- 顶栏 `execControls` 新增 `exportSubtaskBtn`（导出子任务）、`importResultsBtn`（导入结果）。
- body 末尾新增两个模态层（复用 `.help-overlay` 遮罩 + `.help-panel.subtask-panel` 骨架）：
  - `subtaskExportModal`：显示"将导出当前范围 N 条用例（sheet 分布）"、测试人员输入框（可空）、结果列只读提示、导出/取消按钮；无筛选时按钮提示"先筛选出要分发的用例"仍可全量导出（二次确认）。
  - `subtaskImportModal`：文件选择 + 上传按钮 → 预览区（匹配状态统计、结果列表头、差异表格：用例标题 | 字段 | 主文件值 | 子文件值，冲突行高亮）+ "只选空缺"（默认已应用）/"全选"/"清空" + 确认合入/取消。

## 前端：static/app.js

- `exportSubtask()`：收集 `visibleIndices()` 对应 `sheet+rowIndex` → 弹模态 → `POST /api/subtask/export`（blob 下载）→ 成功后 toast 并重载数据（主文件 tester 列已更新）。
- `importResults()`：`FormData` 上传 → 渲染预览表（冲突红标、空缺绿标、未匹配灰列不参与勾选）→ 默认仅勾选"主文件为空且子文件有值"的行字段 → 确认后 `POST /api/subtask/merge` → 展示合入结果摘要（merged/skipped/failures）→ 重载主数据。
- 预览与合入期间禁用其他写操作按钮，防并发。

## 前端：static/style.css

- 模态框（`.help-overlay` + `.help-panel.subtask-panel`，导入预览用 `.subtask-panel-wide` 加宽至 760px）复用遮罩/面板骨架；差异表格、冲突/空缺/未匹配三态行底色用现有 token；按钮沿用 `.btn` 体系（新增 `.btn-primary`）。

## 实现落地说明（相对本文档的代码化调整）

- 新增 `_similarity(a, b)`（difflib 比值，阈值 `_FUZZY_THRESHOLD=0.82`）与 `_subtask_fingerprint(case_id, title, steps)`（sha1，仅用不可变身份字段，导出/合入共用）。
- `_parse_workbook_unlocked` 跳过 `_qoder*` 前缀 Sheet，防止隐藏元数据页被误判为用例页。
- `_import_store`（importId → 子文件临时路径）保存导入会话；合入成功/失败后均失效，残留由启动清理兜底。
- 前端所有新元素 id 已注册进 `IDS` 数组；`onKey` 增加两个新模态的 Esc 关闭分支。

## 测试计划

1. 语法门禁：`py_compile app.py excel_service.py`、`node --check static/app.js`。
2. 脚本级验证：构造主文件（双 Sheet、含已填结果）→ 导出子任务断言（结构/元数据/结果列单一/tester 写入）→ 修改子文件结果 → 预览断言（精确匹配、空缺勾选集、冲突识别）→ 合入断言（默认不覆盖已有值、空缺被补齐、fingerprint 防错位、主文件缺少结果列时报错、sourceFile 不符警告路径）。
3. 回归：真实文件单/多结果列解析写回行为不变。
4. E2E（browser-use）：筛选 P0 导出 → 修改子文件 → 导入预览（冲突/空缺标识正确）→ 确认合入 → 下载主文件核对；控制台零报错。测试后清理临时文件与服务器。

## 假设

- 辅助人员可改动子文件行内容但不增删行（增删行由模糊兜底匹配尽力处理，未匹配条目在预览中列出由主测人工处理）。
- 子文件结果列表头名须与主文件某一结果列一致才能合入（按表头名匹配写入）。
- 分发记录只写"测试人员"列，不新增分配状态列。
